# 用户主动采集代理残留现场

工具：`Scripts/Collect-ProxyDiagnostics.ps1`，双击入口为同目录的 `Collect-ProxyDiagnostics.cmd`。把这两个文件一起交给用户即可，不需要安装 .NET，不要求管理员权限。工具只读取配置，不修改代理、不关闭程序、不注册自启动。执行策略参数仅作用于本次 PowerShell 进程。

## 采集步骤

1. 打开 singC，启用发生问题的模式，保持浏览器运行。
2. 双击 CMD，出现等待关闭的提示后，按用户平时的方式关闭 singC。
3. 等待脚本完成。桌面的 `singC-proxy-diagnostics` 中会新增一个目录，包含运行时、观察到退出时、退出约 2 秒和约 10 秒后的快照。
4. 下次开机发生故障时，**先不打开 singC**，在脚本目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Collect-ProxyDiagnostics.ps1 -SnapshotOnly
```

5. 启动 singC 后恢复访问，再运行一次上面的快照命令。把三组目录交给开发者，并附 singC 版本、浏览器名称、关闭方式、关机间隔及错误页底部错误码。

输出文件可能含代理地址、端口、内部域名，请先检查后再发送。工具不采集浏览历史、Cookie、账号、密码、完整 sing-box 配置或完整浏览器配置文件；URL 凭据、路径、查询参数和片段被删除。用户自定义绕过域名仍会保留，便于判断恢复冲突。

## 证据与局限

- 系统代理：当前用户/机器相关注册表字段、连接配置二进制数据的指纹（用于比较变化）、WinHTTP 的只读代理查询。
- 浏览器：Chrome/Edge 代理策略及磁盘代理偏好，Firefox 允许列表中的代理偏好；不输出配置目录名称和其他偏好内容。
- singC：模式、可读取的版本、进程 ID/启动时间、恢复记录的修改时间及脱敏字段。
- [未验证] 磁盘偏好与策略不能证明浏览器某次请求实际使用了哪个代理；扩展、命令行覆盖、内存缓存和浏览器网络日志需要另行排查。
- 锁定的恢复文件标记为不可读取，不作为记录缺失或已恢复的证据。不存在浏览器代理偏好也不能据此断言走直连。
- 默认最长等待 30 分钟；多个原有 singC 实例全部结束后才记录退出。脚本被关机终止后不会自启动，开机现场需用户主动执行快照。
- 工具不发起网站请求，避免把网站自身可达性误当成代理恢复结果。

比较运行时与退出后的 `ProxyEnable`、`ProxyServer`、`AutoConfigURL` 及恢复记录，判断是否仍启用本地代理；比较启动前的故障快照与恢复后的快照，识别是哪项配置变化使访问恢复。结论仍需结合错误码和用户操作时间，不凭配置差异直接断言根因。
