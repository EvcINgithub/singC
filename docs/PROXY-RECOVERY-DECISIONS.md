# 系统代理字段恢复决策表（历史备选，未采用）

2026-10-15 用户明确选择更简单的策略：系统代理租约结束时，无条件恢复本次启用前的完整状态，覆盖期间外部修改；TUN-only 租约保持原匹配规则。下文按字段合并、归属判断及额外核验为历史备选，不作为当前行为或实施授权。当前规则见 [代理恢复日志说明](PROXY-RECOVERY-LOG.md)。

## 结论与范围

建议将恢复改为“按字段及其依赖关系撤销本次修改，回读核验后结束恢复记录”。整体匹配仍可快速恢复，但要先排除原设置同地址代理的归属歧义。辅助字段变化不能单独阻止清理本次代理；冲突或失败不再静默丢弃依据。本文件为拟议规则，未修改实现，也不涉及独立监护、自启动或强杀后的即时清理。

本备选形成时，源码采用整体相等判断，位置为 `Helper/SystemProxyLease.cs` 的 `RestoreJournal`；该行为已由上方所述最终策略替代。用户提供的历史日志确认过 Bypass 差异跳过并清空记录；后续从代理关闭状态开始的日志恢复正常。附件与详细分析保持在 Git 忽略目录，不复制到本文件。

## 术语和判定前提

| 记号 | 含义 |
|---|---|
| O（Original） | 本会话修改 Windows 代理前的配置 |
| A（Requested） | singC 请求写入的配置；现有日志中的 Applied 属于此类，尚无写后回读 |
| E（Effective） | 新实现写入后立即读回并核对的实际配置 |
| C（Current） | 恢复时读到的当前配置 |
| R（Result） | 根据决策表计算的恢复目标 |
| 本次地址 | 会话记录中 singC 实际使用的监听地址和端口，不假定为 7890 |
| 所属条目 | singC 本次明确写入、写后确认生效且恢复时仍指向本次地址的协议代理条目 |

代理条目通常是 `http=地址:端口;https=地址:端口` 中的一项。Windows 只有一个手动代理总开关，并不是每个协议各有开关，因此地址和启用状态必须联合决策。

**自动归属判断的限制**：Windows 不记录这些字段由哪个应用拥有。相同地址不能排除其他程序复用同一端口，同值也不能证明期间没有人修改后又改回。默认只撤销本次有记录的改动，证据不足时保留并提示。

## 一、整体决策顺序

按下表从上到下执行，先匹配的优先。

| 编号 | 条件 | 行为 | 恢复记录 |
|---|---|---|---|
| G1 | 记录缺失/为空 | 无恢复任务，不推测原值 | 不生成伪造备份 |
| G2 | 记录损坏、版本未知、端口/会话身份无效 | 不写代理，提示恢复依据无效 | 原文件保留 |
| G3 | 另一活跃会话持有恢复锁 | 不抢占 | 保持 |
| G4 | 原设置已经启用本次同地址代理，且无法证明其为可清理残留 | 进入“原始同地址”规则，不能因整体相等就盲目恢复/删除 | 等待明确选择 |
| G5 | C 与 O 完全一致 | 无需写入；核对后记为“已恢复/无需操作” | 持久完成后清理活动记录 |
| G6 | C 与 E 一致，且不触发 G4 | 完整恢复 O，随后回读核验 | 成功才清理 |
| G7 | C 与 E 不同 | 进入下述字段合并规则 | 成功、冲突分开处理 |
| G8 | 无有效 E，仅有旧格式 O/A | C 与 A 完全一致且无歧义时按原流程恢复；否则只处理可证明的条目，其余冲突 | 不自动把当前状态当作 E |

记录格式升级需要保留旧 O/A。写入后读回不同，不能直接把所有读回内容归为 singC 所有：应核对本次地址及目标启用状态，保存差异；无法确认时停止进一步激活并报告未就绪。

## 二、HTTP / HTTPS / 其他协议地址

| 编号 | 恢复时的情况 | 地址处理 | 启用状态处理 |
|---|---|---|---|
| S1 | C 的该协议条目等于 O | 保留，不重复写回 | 交由总开关规则 |
| S2 | 条目仍为本次地址，O 原来启用其他地址 | 将该条目恢复为 O 对应地址 | 有效原代理可按总开关规则继续启用 |
| S3 | 条目仍为本次地址，O 原来没有此协议条目 | 删除本次条目 | 依据剩余代理判断 |
| S4 | 条目仍为本次地址，O 原来保存了地址但手动代理关闭 | 优先撤销本次条目；只有总开关保持关闭、且不存在冲突时，才恢复原先停用的地址配置 | 不允许为了还原地址而重新启用旧代理 |
| S5 | C 已改成不同地址 | 保留当前条目，视作不属于本次的修改 | 不因本次退出关闭该外部代理 |
| S6 | 本次条目已被删除 | 保留删除结果，不重新创建 | 按当前剩余条目处理 |
| S7 | C 新增了本次未管理的协议，如 SOCKS/FTP | 原样保留 | 当前已启用时不得无条件关闭总开关 |
| S8 | O 与本次地址相同，且 O 原来启用 | 不套用 S2/S3，按原始同地址规则处理 | 默认不自动关闭 |
| S9 | 字符串格式无法可靠解析、重复协议含义不明或协议未知 | 不靠字符串替换强删；能整体无歧义恢复时整体处理，否则提示冲突 | 不猜测启用状态 |

解析必须保留未管理的协议和地址，区分全局单一代理地址与按协议代理。单一全局地址在无外部地址变化时可整体恢复；与外部按协议修改混合且不能无损拆分时转 S9。不能简单以分号拆开后假定所有格式都能安全重组。

匹配地址时只做明确安全的语法规范化，例如可识别的主机名大小写；不通过 DNS 解析把不同名字视为同一代理，不自动把 `localhost`、`127.0.0.1`、`::1` 当作同一个监听端点。

## 三、手动代理总开关

**启用标志（Flags）**是多个开关的组合，不应整体覆盖以恢复其中一个位。以下规则在协议条目合并后计算。

已知位：直接连接为 1、手动代理为 2、PAC 为 4、自动检测为 8。直接连接位需要与最终连接方式成组处理，不独立回退成“所有连接方式都关闭”；无法生成合法组合时返回冲突。完整恢复路径仍按经过验证的 O 还原。

| 编号 | 条件 | 手动代理开关 |
|---|---|---|
| M1 | C 已关闭手动代理，且 C 不同于 E 的开启状态 | 保持关闭，不能重新开启已被用户/其他软件关闭的代理 |
| M2 | 本次代理全部撤销，没有外部启用条目，O 原来关闭 | 关闭 |
| M3 | 仍有被外部修改/新增的有效条目，C 当前开启 | 保持开启，不恢复 O 中原先停用的地址到其他协议槽位 |
| M4 | C 仍为本次开启状态，O 原来启用其他地址，且完整恢复了对应原条目 | 恢复原启用状态 |
| M5 | 启用状态和地址归属相互矛盾、或地址无法解析 | 保留无歧义的现状，报告冲突，不写一个猜测状态 |

重要例子：O 里存有一个**关闭状态**的旧 HTTP 代理；运行中外部软件新增并启用了 HTTPS 代理。撤销 singC 的 HTTP 条目后，应保留外部 HTTPS 并保持开启，但不能同时把 O 中那个原本停用的 HTTP 代理重新装回并间接激活。

## 四、Bypass、PAC、自动检测及其他标志

**绕过列表（Bypass）**决定哪些目标直连；**PAC（代理自动配置脚本）**通过脚本决定代理路径。PAC 地址与其启用位是一组相关字段。

| 字段/组 | C 仍等于 E，且本次确实改动 | C 已等于 O | C 变成第三种值 |
|---|---|---|---|
| Bypass | 恢复 O；若需保留外部代理但恢复会明显改变其范围，转冲突 | 不写 | 保留 C，不因它不同而阻止撤销本次 HTTP/HTTPS 条目 |
| PAC 地址＋启用位 | 作为一组恢复 O | 不写 | 保留外部新地址及启用状态；地址改变但开关仍处于本次禁用状态时，不自动启用新脚本，报告未自动恢复部分 |
| 自动检测位 | 仅还原本次改动的这一位 | 不写 | 保留可观察到的外部变更 |
| 其他/未知标志 | 未管理位原样保留 | 不写 | 不整包 Flags 覆盖；无法理解的模式转冲突 |

“本次确实改动”指 O 与 E 在对应字段/位不同。如果本次没有改动某字段，就没有撤销它的必要。

Bypass 顺序或字符串形式变化不能直接归因于第三方；本方案不依靠随意排序/删项来判断所有字符串等价。保留外部 Bypass 可能仍使部分网站直连，这不等于代理恢复失败，应在结果中明确说明。

## 五、TUN 模式单独规则

TUN 模式当前只临时改变代理启用标志，Server/Bypass/PAC 地址通常保持原值，因此不能套用“删除本次代理条目”。

| 编号 | 情况 | 行为 |
|---|---|---|
| T1 | 相关字段及位仍为本次禁用后的状态 | 恢复 O 中被禁用的位；启用前核对依赖地址仍为 O |
| T2 | C 已恢复 O | 不写，视为已恢复 |
| T3 | 外部已经启用另一代理或脚本 | 保留，不覆盖成 O |
| T4 | 代理/PAC 地址被外部改动，但相应开关仍关闭 | 保留地址且不自动开启，报告冲突；不能把旧开启位套到新地址上 |
| T5 | 原状态含归属不明的同地址代理 | 按原始同地址规则，不擅自重启该代理设置 |

这些规则只处理 Windows 代理设置，不声称解决 TUN 的网卡、DNS、路由问题。

## 六、原始同地址代理与旧残留

| 情况 | 默认行为 | 用户可选择 |
|---|---|---|
| O 已启用本次同地址代理，缺少可靠归属记录 | 在启动前提示“原设置已使用该地址”；不自动认定残留，不隐藏这一状态 | 保留并在停止后恢复原状态；或明确确认这是旧残留并清理 |
| 历史恢复记录完整、已确认属于 singC 且无活跃持有者 | 先按对应历史记录处理，再读取新 O | 冲突仍需确认 |
| 仅因端口无人监听推测是残留 | 不自动删除 | 用户明确确认后处理 |

选择“清理旧残留”是独立授权：先持久保存待执行目标，再回读核验；成功后以清理后的状态建立新会话基线。不得简单把旧 O 改写成“关闭”来掩盖实际系统状态。

启动前歧义没有解决时，不开始新的需要修改代理的会话。对已在运行的旧会话发现歧义，应保留依据并提供“保留当前状态并退出”等明确选项；不能无限阻止用户退出，也不能静默报告已完全恢复。

## 七、执行、核验与记录生命周期

| 阶段 | 规则 |
|---|---|
| 写入前 | 持有独占租约，读取 C，生成 R 和逐字段理由；原子保存恢复计划，随后再写代理 |
| 并发变更 | 紧邻写入前再次读取。与计划基线不同则重新计算；连续变化时停止，提示冲突。Windows 写入没有本方案可依赖的字段级比较交换保证，不能声称彻底消除竞态 |
| 写入范围 | 优先只写需要改的字段；若后端仍整体写入，必须合并最新外部字段，不能拿早先 C 整份覆盖 |
| 写入后 | 回读验证本次目标字段和应保留的外部字段；不要仅凭 API 成功返回清空记录 |
| 有限重试 | 默认最多 3 次；重新读取、重新计算，只对仍属本次且适合重试的项重试，不反复覆盖冲突设置 |
| 部分成功 | 保存哪些字段已处理及新的预期状态，避免下一次按旧 A 重复覆盖；返回“部分恢复/仍有冲突” |
| 完全成功/无需操作 | 先持久标记完成，再清理活动记录；重复恢复应无副作用 |
| 外部设置已完全替代本次设置 | 不再强行回退；确认已无本次生效条目后归档为“外部接管”，不称作“已恢复原配置” |
| 冲突/读写失败/记录损坏 | 保留恢复依据，返回具体字段、错误及建议；禁止无条件 SetLength(0) |
| 下一次启动/切换 | 先处理待恢复/冲突状态，防止把未清理的本次代理再次当作 O；不能抢占其他活跃会话 |

恢复计划和备份不受“日志开关”影响；可选诊断日志继续只保存指纹、决策原因和错误码，不输出敏感原文。冲突归档不应无限积累，实施时定义容量及用户清理方式。

## 八、结果状态

| 状态 | 面向用户的含义 | 是否可清理活动记录 |
|---|---|---|
| 已恢复 | 目标字段回读通过，外部修改按规则保留 | 是，先提交完成状态 |
| 无需操作 | 当前已处于目标状态 | 是，核对后提交 |
| 外部接管 | 本次条目已被其他设置替换，未还原原配置 | 可归档后结束活动记录 |
| 部分恢复/冲突 | 已处理部分字段，仍有待确认事项 | 否，保留进度 |
| 恢复失败 | 写入或核验未完成 | 否 |
| 活跃会话 | 恢复锁仍由合法运行会话持有 | 否，不抢占 |

“停止内核成功”与“代理完全恢复”分别表达。内核已经退出但代理冲突时，不应只显示普通“已停止”而隐藏风险。

## 九、验收决策表

所有用例先用模拟后端及临时目录验证。真实代理、关机、网卡测试另行审核；不因批准决策表就默认批准日常电脑上的系统测试。

| 编号 | 输入/故障 | 必须结果 |
|---|---|---|
| V1 | O 手动代理关闭，正常启用后停止 | 总开关恢复关闭，回读成功才完成记录 |
| V2 | V1 连续系统代理/TUN 切换 20 轮 | 不把本次代理当作下轮原状态，无记录叠加 |
| V3 | 只有 Bypass 改为外部值 | 保留新 Bypass，仍撤销本次代理 |
| V4 | HTTP 仍为本次，HTTPS 改为外部地址 | 只撤销/恢复 HTTP，保留 HTTPS 和必要启用状态 |
| V5 | C 新增 SOCKS/未知协议 | 已知且可无损处理时保留；无法解析则冲突，不强删 |
| V6 | C 被用户关闭手动代理 | 停止后仍关闭，不重新激活 O |
| V7 | O 启用公司代理，C 未被外部改动 | 恢复公司代理及其关联启用状态 |
| V8 | O 存有停用 HTTP，C 新增启用 HTTPS | 保留外部 HTTPS，不激活停用 HTTP |
| V9 | PAC 地址及位被外部修改 | 保留外部组，不恢复旧脚本 |
| V10 | TUN 期间 PAC 地址变化但位仍关闭 | 不自动开启新脚本，报告冲突 |
| V11 | O 已启用同地址代理 | 没有确认时不自动删除；确认残留后以真实清理结果建立新 O |
| V12 | 写入返回成功但回读不符 | 不标完成、不清空，有限重试或冲突 |
| V13 | 写入失败、部分写入、进程中断 | 原依据/阶段保留；重试不重复覆盖已完成外部设置 |
| V14 | 计划后外部再次改动 | 重新读取计算；超过次数返回冲突，不无限覆盖 |
| V15 | 损坏/旧版记录、另一实例持锁 | 分别保留提示、兼容判定、拒绝抢占 |
| V16 | 已完成恢复后再次停止/退出 | 幂等，无额外系统设置变更 |
| V17 | 日志关闭或不可写 | 不影响恢复和持久记录 |
| V18 | A/E 字符串形式不同或写后状态非预期 | 只接纳经核实的等效形式；不能把任意读回值当本次所有 |

## 审核与实施边界

待确认的产品选择：

1. 是否接受“保留外部修改优先；不能判定归属时提示冲突”的默认策略。
2. 是否接受原始同地址歧义在启动前确认，默认不擅自清理。
3. 是否接受停止结果区分内核已停止与代理恢复有冲突。

批准后再实施：恢复决策纯函数、可部分写入的 Windows 后端、可恢复的计划记录、UI 冲突反馈，以及上述测试。当前没有改业务代码、自动更新、架构现状或用户系统设置，也没有执行功能测试；文档经字段依赖和反例核对，仍是待审核方案。
