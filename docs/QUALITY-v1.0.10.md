# v1.0.10 验证范围与限制

本次实现用户选择的强制恢复策略：结束系统代理会话时恢复启用前快照，外部软件在会话期间修改的代理配置会被覆盖。TUN-only 会话继续匹配恢复。实现和隔离测试已完成，未操作真实系统代理、路由或 DNS，未执行真实用户安装更新。

## 结果与证据

| 检查 | 结果 | 范围 |
|---|---|---|
| 完整应用回归 | 688 项通过 | 多种原始设置和外部修改、读取失败、写入及部分写入失败、重试、旧备份、幂等、重复模式切换等 |
| 标准 x64 Release | 成功，零警告零错误 | 编译器及默认分析器 |
| Coverlet 分支覆盖 | 26/26，100% | SystemProxyLease.cs，完整回归；行及方法覆盖 100% |
| Stryker 变异得分 | 82/100，82% | 恢复模块独立副本；82 杀死、17 存活、1 未覆盖、0 超时；14 编译错误及 25 工具过滤不计分 |

覆盖率说明测试执行过哪些工具识别的分支；变异得分说明测试能检测多少人为代码变化，均不能保证真实系统行为完全正确。变异包装器调用新增恢复、日志、日志设置测试及原有模式纯逻辑测试，与完整回归的执行范围不同。存活变异涉及日志文字、目录、IPv6 格式、初始绕过列表和磁盘刷新等，未据此执行额外重构。

恢复决策 `forceOriginal || current == Applied` 的四种组合及读取异常过滤条件均有隔离用例；这是手工决策检查，不称为工具认证的 MC/DC 或认知复杂度结果。相关代码完成 24 项异味及资源、异常、依赖检查，细节和原始证据保存在本地忽略目录 `artifacts/validation/forced-proxy-restore-20261015/`，包括 report.md、regression.log、release-build.log、coverage.json、source-hashes.json 和 mutation/ 报告。

## 行为限制与后续验证

- 启用前代理已开启时，恢复后仍开启；本策略不是无条件关闭所有代理。
- 写入失败保留备份，不能声称系统已经恢复；未新增写入后的系统读回校验。
- 进程被强制结束、突然断电或内核停止失败，仍可能无法立即恢复。没有增加独立进程或自启动。
- 真实关机、浏览器缓存及其他软件同时改写代理尚未进行现场验收；代理诊断日志无法证明 TUN 网络故障的原因。

复现：`dotnet run --project Tests/UpdateTests.csproj -c Release`；`dotnet build singC.csproj -c Release -p:Platform=x64 -r win-x64`。发布时另由 Release 工作流执行干净打包、真实包校验和隔离更新器交接测试。
